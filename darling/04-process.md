# 04 — как работать

## Порядок

1. **Вопросы.** До любой работы — пронумерованный список коротких вопросов.
   Для сайта про IDEA их было 11: для кого, язык, как делать логику, стек, какие
   функции, сколько теории, структура, можно ли его картинки, эффекты и звук,
   любимые референсы, устройства. Ответы — в `01-brief.md`.
2. **Ресёрч.** Два направления:
   - **дизайн** — как это делают люди: живые сайты в нужной эстетике (готика,
     angelcore, webcore), леттеринг, разбор референсов заказчика. Не «как я обычно
     делаю», а «что делают дизайнеры, которые это любят»;
   - **предмет** — первоисточники (для IDEA: статья Lai–Massey, тест-векторы,
     известные атаки), а не пересказы. Числа и даты проверять.
3. **Сборка.** Сначала каркас и логика, потом вид. Демо должны реально работать
   на настоящем коде, а не быть картинкой.
4. **Проверка.** Скриншоты каждой секции (`tools/shot.cjs`) и прогон всех демо
   в браузере (Playwright). Смотреть скрины глазами, а не только «тесты прошли».
5. **Показ.** Изменения вида — скрином заказчику **до пуша**. Ждать ответа.
6. **Пуш.** Коммит с понятным сообщением, пуш в рабочую ветку. PR — только по просьбе.

## Правки

- Менять только то, что попросили. Если правка «убрать ИИ-штучки» — не трогать
  демо, логику и любимое меню.
- Если что-то может сломать то, что нравится, — спросить, а не делать молча.
- Если задача тяжёлая или противоречит ограничениям — сказать заранее.

## Технические ограничения сайта

Сайт должен открываться двойным кликом по `index.html` (протокол `file://`):

- **Только классические `<script>`**, без `type="module"` — модули на file://
  блокируются.
- **WebAssembly вшит в JS** как base64 (`assets/wasm/idea_wasm_bytes.js`,
  `window.IDEA_WASM_BASE64`), wasm-bindgen собран с `--target no-modules`.
  Сборка: `scripts/build-wasm.sh`.
- **Данные для канваса** — в JS (`angel-data.js`), а не загрузкой картинки:
  иначе `getImageData` на file:// падает из-за tainted canvas.
- **Без `<link rel="preload" crossorigin>` для шрифтов** — на file:// блокируется.
- **Шрифты свои** (woff2 в `assets/fonts/`, лицензии OFL рядом), никаких CDN.
- `localStorage` может быть недоступен — каждое обращение в `try/catch`, сайт
  работает и без него.
- Деплой: это чистая статика — GitHub Pages или Cloudflare Pages как есть.

## Код

- Логика — на Rust, уровень «сеньор»: `no_std` + `alloc`, `unsafe_code = "forbid"`
  и `clippy::pedantic` в `[workspace.lints]` без предупреждений, `zeroize` для ключей, официальные
  тест-векторы в `crates/idea/tests/`. Формат файлов: magic, версия, режим, IV,
  HKDF-SHA256 → ключ шифра + ключ MAC, HMAC-SHA256, зашифрованное имя файла,
  потоковая обработка.
- JS — простой, без фреймворков и сборки, комментарии по делу.
- Ошибки из Rust — понятным текстом для человека, на обоих языках.

## Перевод

- Английский — в HTML. Русский — словарь, ключ = английский текст.
- Переводить живым языком, а не калькой; термины шифрования — как в русской
  литературе (подключ, раунд, расписание ключей, режим сцепления блоков).
- После перевода — вычитка вторым проходом: смысл, термины, длина строк в вёрстке
  (русский длиннее — проверить, что ничего не налезает), скрины RU-версии.

## Скриншоты

```bash
node darling/tools/shot.cjs file://$PWD/index.html hero.png
node darling/tools/shot.cjs file://$PWD/index.html full.png 1440 900 1
node darling/tools/shot.cjs file://$PWD/index.html ru.png 1440 900 0 "I18N.set('ru')"
```

Вьюпорт по умолчанию 1440×900 — типичный ноутбук. Проверять ещё 1280 и 1920.
